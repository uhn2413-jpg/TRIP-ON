# TRIP:ON v0.15.7

## 새 여행 1단계 UI 정리
- `여행 이름 / 여행지 / 여행 시기 / 여행 기간`의 시각적 계층과 간격을 다시 정리했습니다.
- 새 여행 만들기 1단계에서 라벨과 입력칸 사이의 간격, 섹션 사이 간격, 입력 높이를 보다 일정하게 맞췄습니다.
- 작은 모바일 폭에서도 글자가 잘리거나 선택칸이 비정상적으로 좁아지지 않도록 별도 반응형 규칙을 추가했습니다.

## 국내 여행지 선택 UI
- `시·도 / 시·군·구 / 읍·면·동`을 큰 세로 블록 대신 **라벨 + 선택칸 한 줄** 형태의 compact row로 변경했습니다.
- 선택칸은 남는 가로폭만 사용하고 긴 지역명은 레이아웃을 밀어내지 않도록 처리했습니다.
- 시·군·구를 선택하면 읍·면·동 목록을 별도 버튼 없이 자동으로 불러옵니다.
- 선택 결과는 큰 회색 박스 대신 작은 요약 줄로 표시합니다.
- `대한민국에서 선택 / 직접 입력` 토글은 유지하되 크기와 여백을 정돈했습니다.

## 여행 날짜 입력 방식
- 기존 `정확한 날짜 / 월까지 / 연도만 / 미정` 4분할 버튼을 제거했습니다.
- `날짜 입력 방식` 선택필드에서 아래 중 하나를 고르는 구조로 변경했습니다.
  - 날짜를 정확히 알아요
  - 월까지만 정했어요
  - 연도만 정했어요
  - 아직 미정이에요
- 선택한 방식에 필요한 입력칸만 아래에 표시됩니다.

## 3박 5일 같은 여행 기간 지원
- 기존에는 `durationDays` 하나로 항상 `총 일수 - 1 = 숙박 수`를 계산했습니다.
- v0.15.7부터 `durationNights`를 별도로 저장합니다.
- 기간 UI를 `숙박 n박 / 전체 일정 n일` 두 칸으로 변경했습니다.
- 예: `숙박 3 / 전체 일정 5` → `3박 5일`.
- 날짜 미정 여행에서 전체 일수만 입력하면 숙박 수는 기존 방식처럼 자동 제안됩니다. 숙박 수를 직접 바꾸면 사용자 값이 우선됩니다.
- 정확한 출발일/귀국일을 고른 경우 전체 일수는 날짜로 자동 계산하고, 숙박 수만 별도로 조정할 수 있습니다.
- `durationDays`는 계속 DAY 생성 개수의 기준이므로 기존 일정/복제/후보함 동작과 호환됩니다.

## 기존 데이터 호환
- 기존 여행에 `duration_nights` 값이 없으면 `duration_days - 1`로 자동 보정합니다.
- 당일치기는 `0박 1일`을 내부적으로 사용하고 화면에는 기존처럼 `당일치기`로 표시합니다.
- 오프라인 여행 목록/상세의 기간 표시도 새 숙박 수를 반영합니다.
